# FuelPlan — Implementation Plan

AI-powered race nutrition planner. Users input race details (+ optional GPX), get a detailed nutrition/fueling plan generated by Claude.

---

## Phase 1 — Infrastructure Setup

- [ ] Create new Supabase project (separate from revolution-crit)
- [ ] Run DB migrations: `profiles`, `plans`, `subscriptions`, `plan_credits` tables + RLS policies + auto-profile trigger
- [ ] Create Supabase Storage bucket `gpx-files` (private)
- [ ] Set up Stripe products: `Pro Monthly` (€6/mo), `Pro Annual` (€50/yr), `Pay-per-plan` (€2.50 one-off)
- [ ] Create GitHub repos: `fuelplan` + `fuelplan-be`
- [ ] Add `.env` files (copy from `.env.example`, fill values)
- [ ] Create Render backend service (connect to `fuelplan-be` repo)
- [ ] Configure GitHub Actions for frontend deploy to GitHub Pages

---

## Phase 2 — Auth

- [ ] Supabase Auth: enable email+password + Google OAuth in dashboard
- [ ] `LoginPage.tsx` — sign in / sign up tabs, Google OAuth button
- [ ] `onAuthStateChange` wired in `App.tsx` — session state drives `<RequireAuth>`
- [ ] `OnboardingPage.tsx` — first-time profile setup: sport, weight, supplements
  - On login, check if `profiles.sport` is null → redirect to `/onboarding`
- [ ] Verify `handle_new_user` trigger creates profile row on sign-up

---

## Phase 3 — Plan Generation (core feature)

### Backend
- [ ] `POST /api/plans/generate`
  - `authenticate` + `checkAccess` middleware
  - Accept: `multipart/form-data` with race fields + optional GPX file
  - Upload GPX to Supabase Storage if provided
  - Build Claude prompt with race data, user profile (weight, sport, supplements)
  - Call `anthropic.messages.create` with Claude Sonnet (fast + cheap)
  - Save response to `plans` table via `supabaseService`
  - Decrement `used_this_month` or `credits` depending on tier
  - Return `{ planId, planJson }`

### Frontend
- [ ] `NewPlanPage.tsx` — race input form
  - Fields: race name, date, distance (km), elevation (m), start time
  - GPX file upload (optional)
  - Submit → POST `/api/plans/generate` → redirect to `/plans/:id`
- [ ] `PlanPage.tsx` — rendered plan
  - Display plan_json sections: pre-race nutrition, per-hour fueling table, hydration, supplement timing
  - "Download PDF" (stretch)
- [ ] `DashboardPage.tsx` — list of past plans (TanStack Query from Supabase directly)

---

## Phase 4 — Subscriptions & Access Control

### Backend
- [ ] `POST /api/payments/create-checkout` — creates Stripe Checkout Session
  - Subscription (pro) or payment (pay_per_plan credit pack)
  - `metadata.user_id` set so webhook can map back
- [ ] `POST /api/payments/webhook` (raw body, sig verified)
  - `checkout.session.completed` → upsert `subscriptions` or increment `plan_credits`
  - `customer.subscription.updated` → update `subscriptions.status`
  - `customer.subscription.deleted` → set status `canceled`
  - `invoice.payment_failed` → set status `past_due`

### Frontend
- [ ] `PricingPage.tsx` — tier comparison table, CTA buttons call `/api/payments/create-checkout`
- [ ] `AccountPage.tsx` — shows current plan, usage (used_this_month / credits), "Manage billing" link (Stripe portal)
- [ ] Gate the "Generate Plan" button — check subscription from Supabase before even showing the form
