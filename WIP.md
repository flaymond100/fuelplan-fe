- **GPX parsing on FE** at [src/lib/gpx.ts](src/lib/gpx.ts). Native `DOMParser`, no deps. Returns `{ distanceKm, elevationGainM, startLat, startLng, pointCount }`. On file pick in NewPlan, distance + elevation auto-fill (user can override); coords feed the weather card. Naive elevation gain (sum of positive deltas) — over-counts on noisy GPS data; revisit with a small smoothing pass if it becomes a problem.
- **Weather forecast on FE** via Open-Meteo (free, no API key, CORS works). [src/lib/weather.ts](src/lib/weather.ts) is the client; [src/hooks/useWeather.ts](src/hooks/useWeather.ts) wraps it in react-query keyed on `[lat, lng, date]` with 1h staleTime. `WeatherCard` (inline in NewPlan) renders inside the Route section once both GPX and race date are set:
  - Within 16 days → temp range, precip probability, wind. Pure display — no manual chip to "apply" to anymore.
  - Past or beyond 16 days → muted hint "Forecast available closer to race day".
  - Loading / error → loading state / silent fail.
  - When generation is wired up, the FE will pass the parsed forecast (or null) to the backend prompt; the user no longer picks weather conditions manually.
  - `tempToCategory()` in [weather.ts](src/lib/weather.ts) is currently unused by the FE — keeping it because it's the right place for the threshold definitions when BE generation lands.
  - Privacy note: this sends route start coords to Open-Meteo. Worth a tiny disclosure in the UI later if we add a "first plan" onboarding.
